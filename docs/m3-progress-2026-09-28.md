Updated: 2026-09-28. Branch: `codex/m3-one-tree`, based on M2 commit `36c77ba`.

**The first playable one-tree block is implemented and verified in the Editor.** Unity 6000.6.3f1 compiled the project without errors. **102 EditMode tests and 5 PlayMode tests passed**, with no failed, skipped or inconclusive cases. M3 is not accepted on Quest: hardware interaction, comfort, readability, haptics and user comprehension remain open.

## Try the scene

Open `BoostingExperience/Assets/VRExperienceAGB/Scenes/OneTreeLearning.unity` and press Play. The explicit Editor preview uses a fixed camera and mouse clicks. Player builds retain the existing tracked rig and use the configured Meta controller-ray canvas interaction.

- **Explore branches:** choose TRUE or FALSE at each split. The drop moves to the accepted child. A leaf contributes once; the display calls the result a manual route score.
- **Back / Restart:** cancel an unfinished move or remove the last accepted decision and its leaf contribution. Restart returns to the baseline.
- **Next profile / Follow profile:** review one of four synthetic profiles, then start its deterministic route. Step advances one decision; Play advances automatically; Pause/Resume freezes and resumes movement; Replay restarts.
- **Manual takeover:** choosing a branch yourself changes the mode to manual exploration without altering the prepared profile.
- **Forest entry / Return to tree:** use the temporary overview while preserving the accepted route and score. This is not yet the M5 diorama.
- **Seated layout:** lower the presentation by 0.4 m without changing the tracked rig or camera.

The panel always distinguishes the baseline, this leaf's contribution, and the one-tree subtotal. It explicitly says that one of three trees is shown and this is not the full prediction. No arbitrary manual route or partial subtotal is converted into a probability.

## Implementation

| Area | Delivered behavior |
| --- | --- |
| Application | Plain-C# `TreeSession`; immutable snapshots; stable route/event IDs; revision-checked choices; movement completion; safe undo, restart, pause, playback and overview return |
| Presentation | Seven stable node IDs, six labeled branches, platforms, leaf stations, a data-drop actor, current/visited markers and persistent world-space console |
| Input | Meta ray-canvas template connected to the existing rig; single EventSystem; press-time session/revision identity prevents stale releases and duplicate decisions; Editor-only mouse preview |
| Data | Fictional AGB-like model and four profiles bundled as referenced TextAssets; full M2 evaluation provides profile decisions |
| Scene | Separate `OneTreeLearning.unity`; original smoke scene preserved; new scene first in global build settings; Android build profile uses the global scene list |
| Resources | TMP essentials with their license/resources and Unity-generated metadata; URP materials and synthetic data assets |

Session/application code references no Unity or XR assembly. The scene animates the drop and never derives a score from its position. Pending movement can be cancelled; a stale completion callback cannot commit it later. Pointer presses also carry session identity, so replacing a session cannot reuse an old press even when node IDs match.

The generator creates the initial scene through Unity serialization and declines to overwrite an existing scene. Subsequent readability adjustments were made in place through Unity. The final generated scene is tracked, so normal use does not require running the generator.

## Actual evidence

- **EditMode: 102/102 passed.** Includes the unchanged 84 M2 cases plus 18 session cases: four manual leaves, four prepared profiles, repeated/stale choices, cancellation, pause, replay, manual takeover, immutable snapshots, invalid inputs and retained overview state.
- **PlayMode: 5/5 passed.** Saved-scene tests exercise UI pointer events, correct leaf totals and undo, paused drop movement, camera independence when changing posture, four-profile playback/replay, stale presses across session replacement/two pointers, and failed reload clearing old output. These use simulated UI pointer events, not physical controllers.
- Seven model node identities, twelve console controls, no missing scripts in the saved scene. The original smoke scene remains in the build list after the new scene.
- Actual Editor camera captures were inspected. Initial small labels were enlarged and tree levels separated; branch text was split across two lines. An Editor screenshot is not Quest readability acceptance.
- Before the native TMP trust dialog was confirmed, a standalone Roslyn compilation and 18 Mono session assertion checks passed. Those supplementary checks were subsequently superseded by the actual Unity test runs above.

Reports and screenshots are local and ignored under `artifacts/m3-one-tree-2026-09-28/`. The checked-in test suite and fixtures make the automated checks reproducible.
